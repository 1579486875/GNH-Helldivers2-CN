# 绝地潜兵 2（Helldivers 2）模组 —— 全面审查与修复（通用模板）

> **模板里所有【】都是硬性要求，不是建议。**
> 唯一例外是 **§0.1 力度分级** —— 它决定这一轮要走哪些节。

> **本模板由 RimWorld 版改写，技术底座完全重写。** HD2 的模组不是 XML + CLR，
> 而是 **Stingray bundle（`9ba626afa44a3aa3.patch_N`）+ Lua**；加载顺序不是 `ModsConfig.xml`，
> 而是 **Arsenal 列表位置 → patch 编号**；语言不是 `DefInjected`，而是
> **Lua 词表 / 字符串池 / `_G.BingusTranslations`**。
> 凡标「实测」的断言都来自本项目 2026-10-04 ~ 2026-10-28 的真实事故，可逐条复验。

> **v1 覆盖范围**：模组本地维修与兼容、汉化包制作、以及今后自制模组 / 翻译包的发布前审查。
> 不覆盖：绕过 EAC 的做法（明确禁止，见附录 B.6）。

## 速查卡 —— 遇到现象先查这里

> 正文近千行，**不要从头读**。先在表里找现象，找到就直接跳。

### A. 进不去游戏 / 一点启动就退

| 现象 | 最可能的根因 | 去哪 |
|---|---|---|
| 点启动后 **40～45 秒必退**，弹 Sony「此游戏发生错误」 | patch 容器被写坏（记录区脏 / `bundleId` 错 / `res_id` 错） | **B.1 → 附录 A-1** |
| 崩点**每次都落同一个地址**（`helldivers2.exe+0xXXXXXX`） | 确定性 bug，不是随机 —— 按 minidump 定位出错模块 | **§7.2** |
| 崩点落 `lua51.dll` / 新版本无此模块 | Lua 脚本运行时错误（EAC 后 Lua 是静态链接的，崩点会转进主程序） | **B.2** |
| 崩点落 `helldivers2.exe`，且**该模组日志零产出** | 崩在脚本执行之前 = 资源/容器层，不要去查 Lua | **附录 A-1** |
| 卡在 EAC / GameGuard 初始化，或报 error 577 | 反作弊层（未签名 DLL / 被标记 / 需要重装反作弊组件） | **附录 B.6** |
| 装了两个「替换 `boot` 脚本」的 loader | 互相抢同一个入口 | **附录 B.7** |
| 崩点显示 `?+0x0`（地址不在任何模块内） | 跳到已卸载/非法内存，通常是上游 hook 错位 | §7.2 |

### B. 能进游戏，但模组不生效 / 显示异常

| 现象 | 最可能的根因 | 去哪 |
|---|---|---|
| 模组启用了、Deploy 也成功了，**功能完全没变** | 脚本抛错被 `pcall` 吞掉；或首行 `-- HD2-Addon:` 缺失/写错 | **B.2** |
| 汉化**全是英文**，其它模组正常 | 菜单没接管（`_G.ModOptionsMenu` 不存在或结构变了） | **B.3** |
| 汉化**部分中文部分英文** | 词表没覆盖到的键；或大写/小写两套键只补了一套 | **B.3** |
| 汉化**乱码 / 错位 / 界面崩** | 字符串池长度被改（offset 表错位） | **附录 B.5** |
| 某模组**整块从列表消失** | `manifest.json` 解析失败 / 选项 `Include` 路径不存在 | **B.4** |
| 提示「文件冲突」 | 两个 patch 提供同一 `res_id`（这是覆盖关系，未必是错） | **附录 B.3** |
| 明显加载到了**旧版本资源** | 同名资源被低编号 patch 遮蔽（编号越大越优先） | **附录 B.3** |
| 某个选项**拨了没反应** | 选项值被菜单大写化后查表失败 | **附录 B.4** |

### C. 改完没生效

| 现象 | 最可能的根因 | 去哪 |
|---|---|---|
| 改了模组源文件，游戏里没变 | **没 Purge/Deploy**，或游戏没重启 | §5 |
| Deploy 了但还是没变 | 部署到了**孤儿目录**（旧包名目录还在，Arsenal 用的是新目录） | **附录 A-3** |
| 改了 `hd2a_data.json` 被还原 | **Arsenal 退出时写盘覆盖** | **附录 B.8** |
| 看文件时间戳以为「没部署过」 | **Arsenal 复制时保留源 mtime**（时间戳骗人） | **附录 B.8** |
| 汉化包改了但界面没变 | 菜单在构建 UI 时已解析文本，需重开菜单或重启 | §7.3 |
| 汉化包更新后**简介被打回英文** | Arsenal 重新导入时从 `manifest.json` 重读描述，覆盖显示层 | **附录 A-5** |

### D. 验证怎么算过

| 问题 | 答案 | 去哪 |
|---|---|---|
| 怎么算「部署成功」 | Arsenal 日志 `Deployment finished: N succeeded, 0 failed`，且 `N` 等于你启用的模组数 | §7.1 |
| 怎么算「脚本跑起来了」 | **该模组自己的日志文件有本次启动的新内容**（不是「没报错」） | §7.3 |
| 怎么算「汉化生效」 | 游戏内 ESC → 模组，文字**真的变成中文**；或目标界面文字变了 | §7.4 |
| 日志零更新说明什么 | **脚本根本没执行**，问题在它之前的资源加载层 | **附录 A-1** |
| 崩了怎么找原因 | 解析 `%APPDATA%\Arrowhead\Helldivers2\dumps\*.dmp` | §7.2 |
| 「日志没新错误」算过吗 | **不算**。只证明没崩，证明不了功能生效 | §7 |

## 〇、任务与边界

### 【本次目标】

**目标可能是三种，处理方式不同：**

1. **指定模组**（我圈了 / 点名了某几个）—— 圈了几个就查几个，每个当独立项目各自走完全流程。
   **不许只挑一个做完交差，也不许因为「长得差不多」合并处理。**
2. **指定现象**（截图一个报错 / 一段红字 / 某个功能不生效 / 某处没翻译）——
   先把「点」定位到**具体模组 / 具体资源 / 具体行**，定位不出来就说清卡在哪、还要什么信息，
   **不要硬猜一个答案交差**。
3. **指定产物**（做汉化包 / 修兼容 / 发布新模组）—— 按 §6 交付规格走。

**模组名要自己核对**：Arsenal 里看到的是**显示名**（`manifest.json` 的 `Name` 或我改过的中文 label），
和磁盘上的**目录名**、**GUID**、**patch 里的资源路径**常常对不上。
别拿显示名去硬套目录，也别拿目录名去反推资源路径 —— 三者要用 `hd2a_data.json` 串起来查。

### 【铁律】

1. **绝不修改第三方模组的原始文件**，除非本轮任务就是修它。
   汉化一律做成**独立包**（自己的资源路径 `mods/<author>/<name>`），靠运行时接管或覆盖实现。
2. **绝不为了绕过反作弊而改动**：不注入未签名 DLL、不改 EAC 组件、不伪造签名。
   EAC 之后能做的是「用游戏还保留的 Lua API」，不是「找回被删的接口」。
3. **`GUID` / 资源路径 / 模组目录名** 是发布后难以更改的标识 —— 改了会让 Arsenal 引用、存档关联、
   别人的依赖全部失效。除我明确要求外不动。
4. **我已经确认过的成品**（当前是：已发布的汉化包、已定稿的模组排序与选项配置）要动必须先问。
5. **删任何文件或功能之前先备份**，并说明为什么删。
6. **不许为了让报告好看而放宽判据**，也不许把「没验证」写成「已验证」。

### 固定动作（每次动手前）

1. **先确认环境**：游戏版本、Steam build、Arsenal 版本、loader 版本、启用了哪些模组。
2. **先确认 Arsenal 已完全退出** —— 它会写 `hd2a_data.json`，在它运行时改会被覆盖。
   （判据：`Get-Process HD2Arsenal` 无结果）
3. **先备份**：要动的 `patch` / `hd2a_data.json` / `manifest.json` 复制一份带时间戳的副本。
4. **先取基线**：把本轮相关的日志文件各存一份（对比「改前 / 改后」用）。
5. **先做环境快照**（§8 报告要用）：

```
游戏版本        ：<从 Version.txt / exe 文件版本读，不照抄>
Steam build     ：<appmanifest_553850.acf 的 buildid>
Arsenal 版本    ：<logs 头部 / hd2a_data.json 的 appVersion>
Loader          ：<Bingus v? / Boot Mod Loader v? / 无>
启用模组数      ：<hd2a_data.json modsList 里 enabled=true 的数量>
data 里 patch 数：<0..N 是否连续>
反作弊          ：<GameGuard / EAC>
```

### 【性质：这是一次独立复审】

上一轮很可能已经审过。**本轮不许复用任何旧结论** —— 包括「上轮已通过」的项。
旧结论只能当线索，不能当结论；所有判断都要在本轮重新取证据。

### §0.1 力度分级：先定档，再开工

改动规模决定走多少节。改一行说明文字和重写一个 Lua 接管层，不该用同一套流程。

| 档 | 触发条件 | 必须走的节 | 实机验证 |
|---|---|---|---|
| **L1 文档 / 元数据** | 只动 README / manifest 里不参与加载的字段 / 简介 / 注释 | 〇、一(1.1)、二(容器层)、六 | 一轮 Deploy + 启动，确认模式一致、无新增报错 |
| **L2 资源 / 配置** | 动 patch 内容 / 词表 / 选项 / 排序 / 打包脚本 | 〇、一、二、四、五、六、七 | 一轮 Deploy + 目标界面实测 |
| **L3 代码 / 机制** | 动 Lua 接管逻辑 / loader 依赖 / 容器结构 / 多 patch 覆盖关系 | **全部**，含 1.3 与 1.4 | 双环境（有 / 无该模组）+ 完整日志 + 必要时 minidump |

- **拿不准往上取一档。** 同一轮混了不同档，按最高档走。
- **只有 L3 要求「连续一整轮全绿」**；L1 / L2 达到本档判据即可收工。
- ⚠ **定档不用问**，自行判断并在报告第一行写「本轮按 Lx 执行」。
- ⚠ **分档只放宽「走多少节」，不放宽「判据有多严」。**

## 一、四个正统维度

### 1.1 完整性 —— 「它宣称的，是不是真的都在」

- 宣称的每个功能、每个资源、每个选项，是否**真的存在于 patch 里**、**真的被游戏加载**、**真的生效**。
- **README / 简介里写的条目数，与 patch 里实际的 entry 数逐条对得上吗？**
  这一条**必须用清单跑**，不能靠「读了一遍感觉对」：

  | 查什么 | 怎么查 | 失同步的后果 |
  |---|---|---|
  | patch 里的 entry 数 | 解析容器，数 `entryCount` | 说明书写 2 个资源，实际只有 1 个 |
  | 每个 entry 的 `res_id` 是否等于路径的 `murmur_hash_64A` | 逐条算（附录 B.2） | 资源注册到错误路径 → 静默失效或崩 |
  | `manifest.json` 的 `Options[].Include` 指向的目录是否存在 | 逐个 `Test-Path` | 选项指向空目录 → 部署缺文件 |
  | 词表条目数 | 数 `GNH_CN` 的键 | 文档说 1687 条，实际 1679 条 |
  | 覆盖的文本键是否都在目标模组里存在 | 与英文词典做**双向**比对 | 译了不存在的键 = 白做工；存在的键没译 = 漏翻 |
  | 发布包的版本号 | 从**包里解出来的** `manifest.json` 读，不看文件名 | 文件名写 v40、内容还是 v39 |

  ⚠ **代码对、文档错，发出去就是错的说明书** —— 不报错、不崩，只有人照着做才发现。

- **有没有「写好了却没接上线」的半成品？** 这类「哑火」最隐蔽：

  - Lua 函数写好了，但**没被调用**（没有 hook 点、没有 tick 分支）；
  - 资源写进 patch 了，但 `res_id` 算错 → 游戏按路径找不到；
  - 翻译键写对了，但**不在菜单实际读取的那个 mod id 下**；
  - 选项写进 manifest 了，但 `Include` 路径是空的 → 用户拨了却不部署任何东西。

  ⚠ **「日志里没有报错」不等于「代码跑过了」。** 本项目实测：`pcall` 把绝大多数错误吞成一行
  静默失败，**加载照常继续**。所以「没崩」不能当生效证据 —— 必须有**可观测的落地结果**
  （界面文字变了 / 日志里出现你自己打的那行 / 目标数值变了）。

- **每个开关都要真的拨一次**：开关存在 ≠ 开关有效。
  「拨了没反应」比没有开关更糟 —— 玩家会以为问题已经关掉了。
- **文档里的「行为断言」也要核**：README 写的「不覆盖任何文件」「随时可卸」「不会崩」
  这类话，逐条对代码或实测核。
  **数字对得上、描述却是反的，比数字错更坑。**

### 1.2 兼容性 —— 「换一个环境还站得住吗」

**HD2 的兼容性有五个独立的轴，缺一不可：**

| 轴 | 要确认什么 | 判据 |
|---|---|---|
| **游戏版本** | 模组是否针对当前 build | 模组日志里有没有「build 不匹配」的警告；作者更新说明里有没有写支持哪个 build |
| **Loader** | 依赖哪个加载器 / 哪个 API 版本 | `manifest` 的 requires、loader 日志的 revision |
| **Lua 运行时** | **EAC 后是否还依赖 `ffi` / `bit` / `jit`** | 全文搜这三个词 + 看首行是不是 LuaJIT 字节码 |
| **加载顺序** | 覆盖关系是否正确 | patch 编号 vs 声明顺序（附录 B.3） |
| **同资源竞争者** | 多个模组是否提供同一 `res_id` | 全库 res_id 交集（附录 B.3） |

- ⚠ **别信「版本号」** —— HD2 模组作者填版本号的习惯极不统一：
  实测有把 Nexus 版本字段写成 `1`、`3`、`11`（其实是 build 号）的。
  **判断新旧要看「文件时间戳」和「更新说明里的 build 号」，不看版本字符串。**
- ⚠ **别信 `data` 目录里的文件 mtime** —— Arsenal 复制时**保留源文件时间戳**，
  所以 `data\patch_N` 永远显示模组目录里的旧时间。**判「有没有部署」只能看 Arsenal 日志。**
- **EAC 时代（2026-10-20 起，游戏 7.2.0+）的硬边界**：
  `ffi` / `bit` / `jit` 全部消失，任何**读游戏内存**的模组都不能工作。
  这类模组会在第 1 帧**自行关闭**（loader 提供空壳防止崩溃）。
  你要修它，只能等作者改成用游戏保留的 Lua API —— **不要试图找回被删的接口。**

### 1.3 性能友好性 —— 「别让玩家的帧数掉下去」

HD2 的 Lua 是**每帧都跑**的（`update` 被 loader 包装），所以性能问题比 RimWorld 更直接：

| 检查点 | 判据 |
|---|---|
| **每帧钩子** | `update` 包装里是否每帧都做重活（遍历大表 / 字符串拼接 / 全库扫描） |
| **初始化是否会自行收工** | 有没有「做完就 `done = true`」的退出机制；没有的话会一直跑 |
| **重试是否有限次** | 轮询类逻辑（等菜单出现等）必须有上限，不能无限重试 |
| **字符串分配** | 热路径里避免每帧新建字符串（Lua GC 压力大） |
| **日志写入频率** | 每帧写日志会明显掉帧；必须降频或只在状态变化时写 |

**本项目实测的两个正面例子**：
- 汉化包初始化完成后**交还主循环**（`done = true`），之后每帧只剩一次真假判断；
- 重试上限 900 帧（≈15 秒），超时就放弃，不影响游戏。

### 1.4 必要性 —— 「还在的那些，是不是还有存在的理由」

EAC 之后会出现大量「技术性存活但功能已死」的模组。逐个判定：

| 判定 | 含义 | 处置 |
|---|---|---|
| **仍必要** | 功能真的在跑，且玩家需要 | 保留 |
| **已冗余** | 游戏本体已内置同样效果 / 被别的模组完全覆盖 | 建议移除，说明理由 |
| **无法判定** | 缺少实机证据 | **如实标注，不要猜** |

**特别提醒**：不要因为「它加载成功了」就判定「仍必要」——
加载成功只说明脚本没崩，不说明功能还在（EAC 后大量模组是空转的）。

## 二、五个零错误层（逐层给出证据）

> HD2 的失败是**分层**的：容器坏 → 游戏加载崩溃；资源 id 错 → 静默失效或崩；
> Lua 语法错 → 脚本不执行；加载序错 → 被别的 patch 盖掉；运行时错 → 功能不生效但游戏正常。
> **必须先定位在哪一层，再谈修** —— 修错层等于白干。

| 层 | 要确认什么 | 判据 / 手段 |
|---|---|---|
| **① 容器** | patch 文件结构：magic、entry 表、`bundleId`、offset/len、文件总长 | 深度校验脚本（附录 B.1），逐 entry 验 offset+len 不越界 |
| **② 资源** | 每个 entry 的 `res_id` == `murmur_hash_64A(路径)`；无意外的同 id 冲突 | 逐条算哈希比对（附录 B.2） |
| **③ Lua** | 能编译；首行是 `-- HD2-Addon: mods/<a>/<b>`；**不含 ffi/bit/jit/goto/LuaJIT 字节码**（EAC 后） | `lupa` 编译 + 关键字扫描 + 首行检查（附录 B.5） |
| **④ 加载序** | patch 编号与预期一致；覆盖关系正确；没有「低编号遮蔽高编号」 | Arsenal 部署日志 + 全库 res_id 交集（附录 B.3） |
| **⑤ 运行时** | 日志有产出、无报错、目标行为可观测 | 模组自己的 log + minidump（§7.2 / §7.3） |

### 2.1 容器层 —— 最容易「看起来正常但其实坏了」

**必查项（一个都不能省）：**

```
magic(0x00)          == 0xF0000011
entryCount(0x08)     == 0x58 处记录的 u64（两处必须一致）
totalSize(0x20)      == 文件实际字节数
每个 entry 的：
  res_id(0x68+80i)   == murmur64A(路径)          ← 见附录 B.2
  bundleId(+0x08)    == 文件级 0x50 处的值        ← ★ 本项目踩过坑，见附录 A-1
  recordOffset(+0x10)== 该 entry 数据的绝对偏移
  +0x18 / +0x20 / +0x28 / +0x30 == 0             ← ★ 保留字段必须全 0
  length(+0x38)      == 数据长度 + 8
  +0x40              == 0x1000000000
  +0x48              == (entry序号 << 32) | 0x10
  且 offset + length 不越界
```

> **⚠ 这条不是理论风险，是 2026-10-13 一次真实事故（附录 A-1）。**
> 打包脚本只写了 `res_id` / `offset` / `length` 三个字段，其余从「模板」照抄；
> 而模板是特意挑的最小 patch，截取头部时**越过了它的真实数据区**，
> 把模板数据区里的几十个字节当成了第二 entry 的记录 ——
> `bundleId` 被写成脏值，游戏按错误的包标识找资源，**启动即崩，6 次同地址**。
> 而 `magic`、`entryCount`、`totalSize` **全部正常**，所以「结构校验通过」根本查不出来。

**判定**：必须跑 `tools/check_patch_records.py`，输出 **「问题 entry 数 = 0」** 才算过。

### 2.2 资源层 —— `res_id` 必须与路径严格对应

**原理**：`res_id = murmur_hash_64A(资源路径, seed=0)`（64 位，无需 NUL 结尾）。
路径形如 `mods/<author>/<name>`，与 patch 首行注释里的路径**逐字符一致**。

**必查**：

| 查什么 | 为什么 |
|---|---|
| 每个 entry 的 `res_id` 与首行注释路径算出的哈希相等 | 不等 = 资源注册到别处，静默失效 |
| 全库所有 patch 的 `res_id` 有无**意外重复** | 重复 = 覆盖关系，要判断是不是设计如此 |
| 覆盖的两个资源**版本是否匹配** | 用旧版内容覆盖新版 = 字段缺失/结构不符 → 崩 |

> **覆盖不等于错。** 实测唯一正当的重叠是汉化包覆盖目标模组的资源（
> 例如 `mods/hd2transmog/foundation` 被汉化包覆盖）—— 那是有意的。
> 但**覆盖方必须与被覆盖方的版本对齐**，否则会出现「新版模组 + 旧版汉化资源」的错配。

### 2.3 Lua 层 —— 语法、入口、运行时依赖

**三步，缺一不可：**

1. **首行必须是** `-- HD2-Addon: mods/<author>/<name>`
   —— loader 用正则 `^%-%- HD2-Addon: (mods/[A-Za-z0-9_]+/[A-Za-z0-9_/]+)` 发现模组。
   **少一个空格、路径层级不对，就永远不被加载。**
2. **能编译**：用 `lupa`（Lua 5.1/5.4 皆可做语法检查）编译全文。
3. **运行时不依赖被移除的库**（EAC 后）：

```python
# 必须全部为 0（注释里出现也算风险，宁可人工确认）
BANNED = ['ffi.', 'require("ffi")', 'bit.', 'jit.', 'goto ', '0x..ULL']
# 另外：首 3 字节是 \x1bLJ → LuaJIT 字节码，EAC 后不能执行
```

> **⚠ 「编译通过」不等于「能运行」。** 实测我的汉化包 266 KB 文本编译 0 错，
> 但真正的问题是它的**容器记录区坏了**（容器层），它连执行机会都没有。
> 所以顺序必须是：**容器 → 资源 → Lua**，不能跳。

### 2.4 加载序层 —— patch 编号决定一切

**规则（实测确认）：**

- Arsenal `setTopPriority = false`（默认）时：**列表越靠下 → patch 编号越大 → 优先级越高 → 覆盖前面的**。
- 部署时 Arsenal 按列表顺序依次分配 `patch_0 … patch_N`，**每重排一次编号就整体变化**。
- 游戏按编号升序加载；**同 `res_id` 后者覆盖前者**。

**必查**：

| 查什么 | 怎么查 |
|---|---|
| 目标模组是否真的在预期编号上 | 用 mod 目录里的 patch 与其 `res_id` 反查 `data\patch_N` |
| 编号是否连续 | `0..N` 无缺号（缺号会导致部分资源不加载） |
| 覆盖方是否在被覆盖方**之后** | 比较两者编号 |
| 有没有「越权覆盖」 | 全库 res_id 交集，逐对判断 |

> **⚠ 「列表位置」不是「加载先后」的唯一含义。**
> 对**加载器类**模组（Bingus、Boot Mod Loader），它需要在**其他模组之前**接管环境；
> 而对**覆盖类**模组（汉化包），它需要在**目标之后**。
> 两者要求相反 —— 改顺序前必须分清这个模组属于哪一类。

### 2.5 运行时层 —— 日志与转储

**HD2 有三套独立日志，别混：**

| 日志 | 路径 | 管什么 |
|---|---|---|
| **模组日志** | `%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\<模组名>.log` | 每个 Lua 模组自己写的运行记录 |
| **Loader 日志** | 同上目录 + `boot_mod_loader.log`（`%APPDATA%\Arrowhead\Helldivers2\`） | 加载器发现/启动/失败清单 |
| **崩溃转储** | `%APPDATA%\Arrowhead\Helldivers2\dumps\dump-*.dmp` | minidump，可解析出异常模块 |

**判定「活着」的唯一硬标准**：**该模组日志有本次启动的新内容。**
没有 = 脚本没跑（不管 loader 日志说没说成功）。

## 三、代码整洁高效 + 注释要让编程小白看懂

### 3.1 每一条修复都必须能「自动让路」（设计原则，不是可选项）

HD2 的游戏版本更新极其频繁（2026 年 10 月就经历了 GameGuard → EAC 的整代切换）。
所以**任何接入游戏内部结构的代码，必须自带降级路径**：

```lua
-- 反例：直接假设结构存在
host.register_option = wrapped

-- 正例：假设一定失败，失败就退回只做能做的部分
local ok = pcall(function() host.register_option = wrapped end)
if not ok then
    log('无法接管 register_option（可能是只读表），改用补翻方式')
    -- 继续走「只补翻已有条目」的降级路径，而不是放弃或崩
end
```

**判据**：把被 hook 的对象**人为删掉**（临时测试），脚本应当**安静降级并写日志**，
而不是抛错、不是崩、不是静默什么都不做（后者最难查）。

### 3.2 注释必须让「会一点编程但不熟 HD2」的人看懂

本项目采用的写法（可直接复用）：

```lua
-- ─────────────── 一、词表 ───────────────
-- 格式：[英文原文] = 中文译文
-- 键必须与被汉化模组注册时传入的字符串**逐字符一致**，差一个空格就匹配不上。
-- 生成时会额外补一份全大写版本：菜单显示"选项值"和"模组名"时会先转成大写。
```

**要求**：

- **先说「这是什么、为什么要有它」**，再说怎么用；
- **把隐含前提写出来**（「菜单限制的是**字数**不是字节」这种）；
- **把踩过的坑写成注释**（「实测 0.2.0→0.2.1 丢过全部翻译，因为偏移表是写死的」）；
- 不要写「此处调用 X」这种复述代码的注释 —— 要写**为什么**。

### 3.3 命名与结构

| 项 | 要求 |
|---|---|
| 资源路径 | `mods/<author>/<name>`，全小写 + 下划线，**不要中文、不要空格** |
| 文件头 | 第一行必须是 `-- HD2-Addon: <同一个路径>` |
| 全局变量 | 一律加前缀（本项目用 `_G.GNH_CN_*`），避免与别人的全局撞车 |
| 重复加载保护 | 必须有（`if rawget(_G,'X_LOADED') then return end`）—— 菜单重载会二次执行 |

## 四、极端场景：大胆假设，小心验证

### 4.1 游戏大版本更新（最高频）

**表现**：一夜之间全灭 / 部分模组不工作 / 游戏进不去。

**处置顺序（不许跳步）**：

1. **先确认「纯原版能不能进」** —— 全部模组禁用 + Deploy + 启动。
   - 原版能进 → 是模组侧问题；
   - 原版也进不去 → 游戏/反作弊/系统问题，**不要往模组上查**。
2. **确认版本与反作弊**：`Version.txt` / appmanifest / 反作弊组件版本。
3. **逐层判定**：容器（patch 还能被读吗）→ loader（还能不能被启动）→ Lua（还能不能执行）→ 功能（API 还在吗）。
4. **只保留「纯 Lua + 不读内存」的模组**，逐个加回。

### 4.2 反作弊换代（2026-10-20 EAC）

**已确认的硬边界**：

| 能力 | EAC 前（LuaJIT） | EAC 后（PUC Lua 5.1） |
|---|---|---|
| 纯 Lua 逻辑 / UI / 文本 | ✅ | ✅ |
| `loadstring` 动态加载 | ✅ | ✅ |
| `debug.getupvalue` | ✅ | ✅ |
| 读游戏内存（`ffi` + 偏移） | ✅ | ❌ **完全没有** |
| `bit` 运算 | ✅ | ❌（除非 loader 提供纯 Lua 实现） |
| `jit` 编译 | ✅ | ❌ |
| 未签名 DLL | ⚠️ 部分可行 | ❌ **被拦（error 577）** |

**结论**：**能修的是「用保留 API 重写」；不能修的是「找回被删的能力」。**
后者一律判「无法修复，等作者/等官方口径」，不要浪费时间也不要做违规尝试。

### 4.3 加载器换代

**现状**：Bingus v20 死后出现两个替代品，**只能装一个**（都替换 `boot` 脚本）：

| | Boot Mod Loader | Bingus v21 |
|---|---|---|
| 许可 | MIT，独立实现 | 0BSD 续作，保留原 GUID |
| 能力 | 启动 `-- HD2-Addon:` 模组、逐条报错 | 同左 + 纯 Lua `bit` 库 + `ffi` 空壳 |
| 日志 | `boot_mod_loader.log` | `BingusSharedLoader.log` |

**判定模组是否兼容某 loader**：看它依赖的是 loader 的哪个 API
（`CowboyBingusModLoader.api` / `open_log` / `after_startup` / `capabilities`），
以及是否依赖 `BingusRuntime`。

### 4.4 多 patch 覆盖同一资源

**只有当「覆盖方确实想覆盖」时才合法**。判定：

1. 两个 patch 的 `res_id` 相同；
2. 内容确实不同（md5 不同）；
3. 覆盖方的资源是**为被覆盖方的那个版本**做的。

任意一条不满足 → 是事故，不是设计。

### 4.5 存档 / 配置残留

HD2 的可调状态存在 `%LOCALAPPDATA%\CowboyBingus\Helldivers2\` 下的 `.values` / `.state` 文件里。
模组选项结构变了但旧值还在 → 可能读出错值。

**处置**：先备份，再删对应 `.values`，重进游戏让它重建。
**不要**在没备份的情况下批量删。

## 五、修复 → 复验 → 直到全绿（循环）

```
① 定位到具体层（§2 的五层）
      ↓
② 在【我们自己的产物】里改（不改第三方原始文件）
      ↓
③ 本地静态复验（容器/资源/Lua 三层脚本全过）
      ↓
④ Purge + Deploy（Arsenal）
      ↓
⑤ 启动游戏 → 看日志 → 看功能（§7）
      ↓
⑥ 有一条不绿 → 回到 ①，不许「大概没事就这样吧」
```

**必须留痕**：

- 每次改动**前**备份（带时间戳）；
- 每次改动**后**跑一遍静态复验脚本，把输出记进报告；
- **不许**只在脑子里记「我改过这里」。

## 六、交付：打包、版本、分发

### 6.1 产物结构（Arsenal / HD2MM 通用）

```
<产物目录>\
  manifest.json              ← 必须：Name / Version / Guid / Description / Options
  Addon\                     ← 或 data\，取决于 Options[].Include
    9ba626afa44a3aa3.patch_0
    9ba626afa44a3aa3.patch_0.stream          ← 若 patch 有 stream，必须有同名附属（可 0 字节）
    9ba626afa44a3aa3.patch_0.gpu_resources   ← 同上
  thumbnail.png              ← 260 KB 左右，建议有
```

**三条硬要求**：

1. **`manifest.json` 的 `Guid` 发布后不可改** —— Arsenal 用它识别模组，改了等于变成新模组。
2. **`Options[].Include` 指向的目录必须真实存在且非空** —— 否则用户勾了选项却部署不到东西。
3. **`Name` 里如果带版本号，必须与 patch 内容同步更新** —— 否则 Arsenal 列表里显示的版本是错的。

### 6.2 版本号纪律

| 位置 | 谁在用它 | 必须一致吗 |
|---|---|---|
| `manifest.json` 的 `Name` 里的版本 | 玩家看到的显示名 | 建议与内容同步 |
| 发布包文件名 | 下载/归档用 | 建议一致 |
| **README 里的清单** | 人看的 | **必须与产物实际状态一致** |
| patch 内容 | 游戏实际加载的 | **唯一真源** |

> **⚠ 本项目踩过的坑**：从网上下载的新版模组覆盖旧版后，
> **中文显示名里的版本号不会自动更新**（那是 Arsenal 显示层，不是文件内容）。
> 每次更新模组后必须跑一次「版本号跟随」脚本，否则列表里写 v1.7.4、实际跑 v1.7.5。

### 6.3 分发与合规（**必读**）

| 规则 | 说明 |
|---|---|
| **汉化包可以独立分发** | 前提是它**不包含**第三方模组的原始资源（只放自己的 `mods/<author>/<name>`） |
| **覆盖式汉化要谨慎** | 覆盖别人的资源 = 包含别人的内容 → 分发前确认原作者的授权条款 |
| **禁止打包他人模组** | 尤其是原作者明确写了「禁止重分发」的（当前已知：**HD2 HUD+**，作者声明禁止任何修改版本的重分发，包括非官方续作） |
| **禁止绕过反作弊** | 任何为绕过 EAC 而做的修改都不得分发 |

> **判定方法**：产物里解出来的每个 `res_id` 对应的路径，
> 若路径前缀不是 `mods/<我自己的作者名>/`，就属于「含他人内容」——
> 必须确认授权，或改为「只发布 patch 差异 / 改为运行时接管」的形式。

### 6.4 打包脚本纪律

- **先备份**要覆盖的产物；
- **打完立刻自检**：解压 → 逐项校验（容器/资源/`manifest`）→ 记 SHA-256；
- **文件名不要含空格**（Arsenal/NXM 链路对空格处理不统一）；
- 大文件（>100 MB）不要放 GitHub Release，走别的渠道。

## 七、实机验证（⚠ 硬门禁）

> **这一节是唯一「不许打折」的部分。**
> 静态脚本全绿只证明「文件结构没错」，**证明不了「游戏里真的生效」**。

### 7.1 部署验证（Deploy）

**必须看到**（Arsenal 日志，`%LOCALAPPDATA%\hd2arsenal\logs\hd2arsenal_*.log`）：

```
Restoring game to pristine state...
Removed N mod file(s)
Starting deployment: X total mods, Y enabled, priority: bottom
... （逐模组 Deploying / Deployed ... successfully - N files copied）
Deployment finished: Y succeeded, 0 failed
```

**判定**：

| 检查 | 通过条件 |
|---|---|
| 成功数 | `succeeded == enabled`，且 `failed == 0` |
| 文件数 | 与上次部署相比，差异只应出现在你改过的模组上 |
| patch 总数 | `data\` 里 `0..N` 连续无缺号 |

> **⚠ 不要用 `data\patch_N` 的 mtime 判断部署时间** —— Arsenal 保留源时间戳（附录 B.8）。

### 7.2 崩溃定位（minidump）

**路径**：`%APPDATA%\Arrowhead\Helldivers2\dumps\dump-YYYY-MM-DD-HH.MM.SS-<hash>-<机器名>-<pid>.dmp`

**解析方法**（`tools/parse_hd2_dump.py`）：

```
minidump 结构：
  Header      : "MDMP" + streamCount + streamDirectoryRva
  Stream 4    : ModuleList  → 每个模块的 base/size/name
  Stream 6    : Exception   → ExceptionCode + ExceptionAddress + ThreadContext
  Stream 3    : ThreadList  → 每线程的 Stack 内存范围
```

**判定表**：

| 崩点落点 | 含义 | 下一步 |
|---|---|---|
| `helldivers2.exe+偏移`，且**每次同偏移** | 确定性 bug（资源/容器层最可能） | 查容器（§2.1） |
| `game.dll+偏移` | 游戏逻辑层 | 通常是模组调用参数错误 |
| `lua51.dll+偏移`（旧版） | Lua 运行时 | 查脚本（§2.3） |
| `?+0x0` / 地址不在任何模块 | 跳到非法内存 | 上游 hook 错位 |
| `npgg*.des` / EAC 模块 | 反作弊层 | 查反作弊（附录 B.6） |

**必做对照**：

1. 崩点是否**每次相同** → 相同 = 确定性，不同 = 竞态/随机内存；
2. **该模组的日志有没有产出** → 零产出 = 脚本没跑，别查 Lua；
3. 与**历史的其他崩溃**比是否同一位置 → 同一位置通常是同一根因。

> **⚠ 真实案例**：某次连续 6 次崩溃，异常地址**完全相同**（`helldivers2.exe+0x5F2EB0`），
> 而该模组自己的日志**一次都没更新** —— 结论直接指向「脚本没执行 + 容器坏了」，
> 而不是「Lua 逻辑错」。如果先去查 Lua，会浪费几个小时（本项目实际浪费了近一小时）。

### 7.3 「脚本是否真的跑起来」（最关键的一条）

**判据（唯一有效）**：**该模组自己的日志文件，本次启动后有没有新内容写进去。**

```powershell
# 看目标模组日志的最后写入时间与内容
$log = "$env:LOCALAPPDATA\CowboyBingus\Helldivers2\Logs\<模组名>.log"
Get-Item $log | Select-Object Length, LastWriteTime
Get-Content $log -Tail 30
```

**三种结果对应三种结论：**

| 结果 | 结论 |
|---|---|
| 有本次启动的新内容，且走到「初始化完成」 | 脚本正常执行 ✅ |
| 有内容但停在某一行 | 那行之后出错 → 去查那行的上下文 |
| **文件根本没更新** | **脚本没执行** → 查容器/loader/资源路径，**不要查 Lua** |

> **⚠ 这条比「日志里没有报错」可靠一百倍。**
> `pcall` 会把错误吞掉，所以「没报错」什么都不能证明；
> 而「日志有没有产出」是**硬事实**。

### 7.4 汉化是否生效

**三层验证，逐层收紧：**

| 层 | 怎么验 | 不算过的情形 |
|---|---|---|
| **V1 静态** | 词表覆盖了目标键、长度不超限 | —— |
| **V2 加载** | 汉化包日志有产出、`register_option` 被接管 | 只有「加载成功」不算 |
| **V3 界面** | 游戏内 ESC → 模组，**文字真的是中文**；或目标界面文字变了 | 「应该会变」不算 |

**必须亲眼看到的 V3 证据**：

- 打开模组菜单，确认**至少 3 个**原本英文的选项现在显示中文；
- 检查**选项值**（不是选项名）是否也变中文 —— 那是两套键；
- 检查**说明文本**（description）是否变中文 —— 那是第三个长度限制。

### A-1 ★★★ 打包脚本「记录区污染」→ 游戏启动即崩（2026-10-13）

**现象**
- 点启动后 **40～45 秒必退**，弹 Sony「此游戏发生错误」；
- 连续 6 次崩溃，异常地址**完全相同**：`ACCESS_VIOLATION @ helldivers2.exe+0x5F2EB0`；
- 对比该机器 60 多次历史崩溃，**这个位置从未出现过**；
- 该模组自己的日志 **从 10-10 之后再没更新过**；
- 禁用该模组就能进游戏。

**根因（二进制层面）**
打包脚本 `write_patch()` 每个 entry **只写了 3 个字段**（`res_id` / `offset` / `length`），
其余从「模板 patch」照抄。而模板是特意挑的**最小 patch**（288 字节），
`head_len = 0xC8 + 80*(N-1)` **越过了模板的真实数据区**，
把数据区开头的几十字节当成了第二个 entry 的记录：

```
entry1.bundleId  = 8589934676            ← 应为 11623383793923069922
entry1 +0x18..30 = "mouse wheel hook off…" 的碎片
```

游戏拿错误的 `bundleId` 去找资源 → 定位失败 → 崩在 `helldivers2.exe`。

**为什么极难查**
| 检查项 | 结果 | 说明 |
|---|---|---|
| `magic` | ✅ 正常 | |
| `entryCount` | ✅ 正常 | |
| `totalSize` | ✅ 正常 | |
| 137 个 patch 的 magic | ✅ 全正常 | 只查 magic 永远查不出 |
| **逐字节对比源文件** | ✅ 137/137 匹配 | 内容确实是它自己的 |
| **记录区字段** | ❌ **脏** | **唯一的破绽** |

**教训**
1. **「结构校验通过」≠「结构正确」** —— 只验 magic/count/size 会漏掉字段级污染。
2. **必须逐字段核对记录区**（`bundleId`、保留字段全 0），跑 `tools/check_patch_records.py`。
3. **「日志零产出」是最强信号** —— 它说明脚本没执行，问题在更底层。
   本次因为先怀疑 Lua 逻辑，白走了一小时（先后误判 Bingus 位置、翻译包、词表）。
4. **打包工具必须自带构建后自检**：写脏数据就直接抛错中止，别让坏包子流出去。

**修复**
`write_patch()` 改为：头部只取 `0x00..0x68`；记录区**整体清零后逐字段写全**；
新增 `_assert_clean_records()` 构建后自检。

### A-2 ★★★ 字符串池「等长替换」被破坏 → 全部翻译失效（HUD+ 0.2.0→0.2.1）

**现象**：某 HUD 模组大版本更新后，之前做的全部中文翻译消失，界面变回英文。

**根因**：该模组的文本不是 Lua 表，而是**多语言字符串池 + 32 位偏移表**：
```
[英文段][波兰语段][西班牙语段]…   每段以 NUL 分隔
~0x3128 处有一张 25 项的 u32 偏移表，指向英文段内部
```
一旦任何字符串**长度变化**，后面所有偏移全部错位 → 菜单读到垃圾 / 崩。
新版本里偏移表的位置和项数还变了，旧脚本写死的偏移全部失效。

**教训**
1. **改二进制字符串池只能「等长替换」**：中文短于英文时用 `\0` 补齐，**绝不允许变长**。
2. **改完必须断言文件总长度不变**，并校验偏移表仍全部指向合法位置。
3. **这类改动是「上游一变就废」** —— 版本更新后必须重跑，且脚本要**按模式匹配定位**（`\0 英文 \0`），
   不要写死偏移。

### A-3 ★★ 孤儿目录：Deploy 到旧包名目录 → 汉化永远不生效

**现象**：汉化包在 Arsenal 里显示启用、Deploy 也成功，但游戏里没有任何变化。

**根因**：Arsenal 的模组目录名是 `<显示名>_AR<编号>`。改了包名之后，
**磁盘上同时存在新旧两个目录**，而构建脚本**写死**了旧名 —— 于是每次「部署」都写进孤儿目录，
Arsenal 实际部署的却是新目录（内容还是旧的）。

**证据**：`hd2a_data.json` 的 `modsLibrary[].path` 指向新目录，而脚本输出的是旧目录。

**教训**
1. **构建脚本不许硬编码模组目录名** —— 必须从 `hd2a_data.json` 动态解析。
2. **打完包后核对 `path`**：脚本写入的路径必须等于 Arsenal 实际使用的那条。
3. 定期检查 `mods\` 下有无**未被任何 library 条目引用**的目录（孤儿）。

### A-4 ★★ Bingus 加载器位置：作者文档说的是对的，但**不能只看资源冲突**

**现象**：把加载器从列表首位移到最后，游戏崩；移回来，不崩（当时如此判断）。

**真相**：那次崩溃**另有根因**（A-1），加载器位置是**无关变量**。
但过程中确实暴露了一条重要机制：

- **加载器类模组**（提供 `require` / `package` / `archive` / `-- HD2-Addon:` 发现）
  需要在**其他模组之前**建立运行时环境；
- **覆盖类模组**（汉化资源）需要在**目标之后**才能盖住。

**两者要求相反。** 判断依据是「它提供能力还是提供内容」。

**教训**
1. **改顺序前先分类**：加载器 / 内容 / 覆盖 —— 三类的位置要求不同。
2. **改动顺序后必须重新 Deploy**（编号会整体重排）。
3. **不要把「相关」当「因果」**：那次崩的真正原因是容器坏了，
   位置只是恰好同时变过。**变量控制要做干净**。

### A-5 ★★ 模组简介被打回英文（Arsenal 重新导入时覆盖显示层）

**现象**：辛苦改好的 30 条中文简介，用户更新一次模组后全部变回英文。

**根因**：Arsenal 的**显示层**（`hd2a_data.json` 的 `description`）是从每个模组自带的
`manifest.json` 里读出来的。**重新导入 = 重新读 manifest = 覆盖显示层。**

**教训**
1. **简介汉化是「显示层补丁」，不是内容修改** —— 上游一变就要重跑。
2. **不要改 `manifest.json` 来改简介**：`contentHash` 会失效，模组会被标成「已更改」。
3. 建立固定动作：**每次更新模组后，重跑简介汉化脚本**。

### A-6 ★★ 菜单会把选项值转成大写 → 小写键查表失败

**现象**：某选项值在词表里明明有，游戏里却仍显示英文。

**根因**：菜单显示**选项值**和**模组名**时会先做 `string.upper()`，
然后拿大写串去查表。只补了小写键 → 查不到。

**教训**
1. **词表必须同时提供原样键和大写键**（`['Red']` 和 `['RED']`）。
2. 生成词表时**自动补大写版本**，不要手工维护两套。
3. **译文里避免出现小写拉丁字母**（例如 `x1.1` 会显示成 `X1.1`），必要时改用全角或中文。

### A-7 ★★ 翻译包结构：文档有，但要**先找官方文档再下手**

**现象**：为把某些子模组的文本也汉化，尝试向全局翻译表注册，一度怀疑格式错。

**真相**：官方 Bingus Text 的规范**写在源码注释里**，结构是：

```lua
_G.BingusTranslations = {
    version = 1,
    serial  = N,              -- 每次变更 +1，各模组靠它判断要不要重查
    packs   = { { language='zh-Hans', name='…', force=false, mods={ mod_id = { key = text } } } },
    override = nil,           -- 最后一个 force=true 的 pack 的语言
}
```

**校验很严**（在 `translator:merge` 里）：
- 键必须存在于该模组的英文词典（unknown key → 跳过）
- **占位符必须与英文完全一致**（`{page}` / `{pages}` 之类，少一个就拒收）
- 长度按**字符数**限制（label 64 / mod 40 / choice 48 / description 400）
- **校验失败只跳过 + 警告，不会崩**

**教训**
1. **先找官方源码注释/README**，不要凭猜。
2. **长度限制的单位是「字符」不是「字节」** —— 这条被官方注释明确写过，别再搞错。
3. **注册后必须 `serial + 1`**，否则各模组不会重查。

### A-8 ★★ 覆盖式汉化的版本错配

**现象**：汉化包覆盖了某模组的一个资源，模组更新后游戏出异常。

**根因**：覆盖方提供的是**旧版本**的资源内容，被覆盖方已是新版本。字段/结构不一致。

**教训**
1. **覆盖式汉化必须记录「基于哪个版本做的」**，每次目标更新都要重做。
2. **优先用「运行时接管」而不是「资源覆盖」** —— 前者不受版本影响（A-2 的字符串池就是被覆盖坑的）。
3. 若必须覆盖，**每次 Deploy 后校验两者的 `res_id` 相同、且内容 md5 不同**（确认覆盖真的发生）。

### A-9 ★★★ 反作弊换代（2026-10-20，游戏 7.2.0）

## 附录 B：技术参考（可直接抄的实现）

### B.1 patch 容器格式（`9ba626afa44a3aa3.patch_N`）

**文件头**

| 偏移 | 类型 | 含义 |
|---|---|---|
| `0x00` | u32 | **magic = `0xF0000011`** |
| `0x04` | u32 | 版本 = 1 |
| `0x08` | u32 | **entry 数量** |
| `0x20` | u32 | **文件总字节数**（必须等于实际大小） |
| `0x50` | u64 | **bundleId**（文件级；每个 entry 的 `+0x08` 必须等于它） |
| `0x58` | u64 | entry 数量（与 `0x08` 一致） |

**entry 记录表**（从 `0x68` 起，每条 **80 字节**，基址 `0x68 + 80*i`）

| 相对偏移 | 类型 | 含义 | 正确值 |
|---|---|---|---|
| `+0x00` | u64 | `res_id` | `murmur_hash_64A(路径, 0)` |
| `+0x08` | u64 | **`bundleId`** | 等于文件级 `0x50` 处的值 |
| `+0x10` | u64 | 数据记录偏移 | 该 entry 数据块的绝对偏移 |
| `+0x18` | u64 | 保留 | **必须 0** |
| `+0x20` | u64 | 保留 | **必须 0** |
| `+0x28` | u64 | 保留 | **必须 0** |
| `+0x30` | u64 | 保留 | **必须 0** |
| `+0x38` | u64 | 数据长度 + 8 | |
| `+0x40` | u64 | 常量 | `0x1000000000`（68719476736） |
| `+0x48` | u64 | 低 32 位 = `0x10`，高 32 位 = entry 序号 | entry0 = 16，entry1 = 4294967312 |

**数据块**（每个 entry）
```
[u32 长度][u32 类型][payload]  + 对齐到 8 字节的 \0 填充
类型：2 = Lua
```

**Lua payload 的形状**
- **文本 Lua**：首行 `-- HD2-Addon: mods/<author>/<name>`，其后是源码；
- **LuaJIT 字节码**：前 3 字节 `1b 4c 4a`（`\x1bLJ`）—— **EAC 后不可用**；
- **转义字节码**：`return assert(loadstring("\027\076\074..."))` —— 同样属于字节码。

**附属文件**：同名 `.stream` / `.gpu_resources` 必须同时存在（可为 0 字节）。

### B.2 `res_id` 计算（murmur_hash_64A）

```python
def murmur64a(data: bytes, seed: int = 0) -> int:
    m, r, mask = 0xc6a4a7935bd1e995, 47, (1 << 64) - 1
    h = (seed ^ (len(data) * m)) & mask
    n = len(data) // 8
    for i in range(n):
        k = int.from_bytes(data[i*8:i*8+8], 'little')
        k = (k * m) & mask
        k ^= k >> r
        k = (k * m) & mask
        h ^= k
        h = (h * m) & mask
    tail = data[n*8:]
    if tail:
        for i in range(len(tail) - 1, -1, -1):
            h ^= tail[i] << (8 * i)
        h = (h * m) & mask
    h ^= h >> r
    h = (h * m) & mask
    h ^= h >> r
    return h

# 用法
assert murmur64a(b'mods/gnh_cn/zh_hans') == 14661701313568333014
```

**纪律**：路径用 **UTF-8 裸字节**，**不要加 `\0`**（加了哈希完全不同，实测差一个量级）。
路径大小写敏感，必须与首行注释**逐字符一致**。

### B.3 加载顺序与优先级

**Arsenal 的两种语义**

| 设置 | 含义 |
|---|---|
| `setTopPriority = false`（默认） | 列表**越靠下** → patch 编号**越大** → **优先级越高** → 覆盖前面的 |
| `setTopPriority = true` | 反过来 |

**部署规则**：Arsenal 按列表顺序依次分配 `patch_0 … patch_N`；**每次重排编号整体变化**。
**游戏按编号升序加载，同 `res_id` 后者覆盖前者。**

**判「谁覆盖谁」的方法**

```python
# 1) 从 Arsenal 状态拿列表顺序
mods = json.load(open(r'%LOCALAPPDATA%\hd2arsenal\hd2a_data.json'))['modsList']['default']['mods']
# 2) 按顺序累加每个模组的 patch 文件数，得到每个模组的编号区间
# 3) 要覆盖别人的那个，必须编号更大
```

**同资源冲突排查**：全库统计 `res_id` 出现次数，>1 的就是覆盖关系，逐对判断是否设计如此。

### B.4 汉化四种方式（按优先级选）

| 方式 | 原理 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **① 运行时接管** | hook 菜单的 `register_option`，翻译传入的 spec；再"补翻"已注册条目 | **不碰任何别人的文件**、天然零冲突、版本更新通常仍有效 | 依赖菜单内部结构；菜单大改会失效（但有降级） | **首选**：选项名/值/说明/模组名 |
| **② 官方翻译包** | 往 `_G.BingusTranslations.packs` 注册 | 走官方正路、有校验保护 | 要求目标模组用该体系；占位符/长度校验严 | 目标模组已接入 Bingus Text 时 |
| **③ 字符串池等长替换** | 直接改 patch 里的二进制文本，**长度不变** | 能汉化不走 Lua 的硬编码文本 | **极易被上游更新打破**；禁止变长 | 只能在①②都不可行时 |
| **④ 资源覆盖** | 提供一份翻译后的资源，覆盖目标的同一 `res_id` | 简单直接 | **版本错配风险高**（A-8）；算"含他人内容"，分发受限 | 最后手段，且必须记录基线版本 |

**决策顺序**：① → ② → ③ → ④。**能运行时接管就不要覆盖。**

### B.5 字符串池等长替换纪律

```python
# 前提：已经定位到"多语言字符串池"（NUL 分隔）与偏移表（u32 数组）
raw = bytearray(open(patch, 'rb').read())
orig_len = len(raw)

for en, zh in REPL:
    needle = b'\x00' + en.encode() + b'\x00'
    if raw.count(needle) != 1:      # 必须恰好命中一次，否则跳过
        continue
    pos = raw.find(needle)
    start, ln = pos + 1, len(en.encode())
    if len(zh.encode()) > ln:       # 中文比英文长 → 跳过，绝不截断英文
        continue
    raw[start:start+ln] = zh.encode() + b'\x00' * (ln - len(zh.encode()))

assert len(raw) == orig_len, '文件长度被改变了！'   # ← 必须
```

**四条铁律**
1. **总长度绝对不变**（偏移表是按绝对偏移算的）；
2. **中文短于英文时用 `\0` 补满**，不要缩短字符串；
3. **放不下的就保留英文**，宁可混排也不破坏结构；
4. **改完必须验证偏移表仍全部指向合法位置**（每个 offset < 文件长度，且指向的字节是字符串起点）。

**反例（A-2）**：某次版本更新后偏移表位置/项数都变了，写死偏移的脚本全部失效。
**所以定位要用「模式匹配」而不是「写死偏移」。**

### B.6 EAC 时代（游戏 7.2.0+）能力边界

| 能力 | 是否可用 | 备注 |
|---|---|---|
| 纯 Lua 逻辑 / UI / 文本 | ✅ | |
| `loadstring` / `debug.getupvalue` | ✅ | 标准库仍在 |
| 游戏保留的 Lua API（units/lights/lines/text/keys/网络字段） | ✅ | 具体清单随版本变，需实测 |
| `ffi`（读写进程内存） | ❌ | 库不存在 |
| `bit` | ❌ | 除非 loader 提供纯 Lua 实现 |
| `jit` | ❌ | |
| 未签名 DLL | ❌ | EAC 拦截（error 577） |
| LuaJIT 字节码 | ❌ | 报 `bad header in precompiled chunk` |
| `goto`（LuaJIT 扩展） | ❌ | PUC 5.1 不支持（5.2+ 才有） |

**硬结论**：**能修的是「用保留 API 重写」，不能修的是「找回被删的能力」。**
后者一律判「无法修复」，并说明依据。**不要尝试绕过 EAC。**

### B.8 Arsenal 行为（必须知道的五条）

1. **Deploy 前会 Purge**：`Restoring game to pristine state...` → `Removed N mod file(s)`。
   所以「Deploy 期间游戏在运行」= 游戏读到被抽走的文件 → 崩（**不要在游戏运行时 Deploy**）。
2. **复制时保留源文件 mtime** → `data\patch_N` 的时间戳永远是旧的。
   **判断是否部署只能看日志，不能看时间戳。**
3. **退出时写 `hd2a_data.json`** → 想手改这个文件，**必须先完全关闭 Arsenal**。
4. **重新导入会重读 `manifest.json`** → 显示层（中文 label / 简介）会被打回英文（A-5）。
5. **每次 Deploy 重排 patch 编号** → 任何「记住 patch 编号」的脚本都会失效。
